# Risiti app 1.2 — Transactions & sign-up (September 2026)

Android `versionName` 1.2, `versionCode` 3. Branch: `transactions`.

**Needs the Risiti server's transactions release**
(`risiti/docs/releases/2026-09-transactions.md`). Deploy the server first:
app 1.2 can't sync with the old server, and 1.1 can't sync with the new one.

## What's new

### One list of transactions
Receipts, refund requests and payment requests are now one kind of record, a
**transaction**, typed expense, refund or payment request, the same as on the
server.

- **Refunds:** "Request refund" on an expense turns it into a refund, paid
  back by M-Pesa to the person's number unless they change it. While it
  waits, "Take back refund request" makes it an expense again.
- **Payment requests** now say:
  - who is paid, and what for;
  - the category;
  - whether it pays a supplier or is an advance to the person.
  They can have attachments, and can be edited after they're sent.
- **Filters:** the home list filters by spending group, or to "Refunds &
  payments".
- **Approvals** is one list, split into *To decide* and *To pay*. It shows
  only for people the server lets approve or pay.

### Sign up on the phone
- **SMS sign-up:** any Kenyan number can sign up. After the SMS code, a new
  number gives a name and chooses:
  - **Just me:** a free personal expense book. There's nobody else to
    approve, so there are no approvals, refunds or payment requests.
  - **My business:** a named team on a free trial, which they own and can
    add people to.
- **No local-only books:** the "Use without a team" option is gone. Books
  that already exist on phones keep working, and can connect from Settings.

### Sign in with Google
"Continue with Google" appears on the sign-in screen once the app is
configured (below).

- A person the server knows goes straight in; someone new signs up as with
  a phone number.
- The book on the phone is kept under a phone number, so Google users also
  give their M-Pesa number. It stays on the phone, for refunds; the server
  only trusts numbers confirmed by SMS.

## Your data on update
On first launch the app moves its data, the same way the server does:

- A receipt with a refund request becomes one refund, decided as its latest
  request was.
- Other receipts become expenses.
- Payment requests become payment requests, dated the day they were made,
  paying the payee, in "Other".
- Attachments follow their transactions.
- Deletions not yet sent to the server are kept.
- Ids and client ids are unchanged, so the next sync lines up with the
  server.

The old tables stay in the database, untouched. The migrations are
`20260928090000_create_transactions` and `20260929090000_add_team_kind_to_profiles`.

## Configuration

| Setting | Where | Needed for |
|---|---|---|
| `config :duka_app, :google_client_id` | `config/config.exs` | Sign in with Google: the **Web** OAuth client id, the same one as the server's `GOOGLE_CLIENT_IDS`. `nil` hides the button. |
| Android OAuth client | Google Cloud console, same project | Package `com.example.duka_app`, with the SHA-1 of **both** the debug and release signing keys (`keytool -list -v -keystore android/upload_jks.keystore`) |

## Building for testers

The app includes a new local plugin, `plugins/mob_google` (enabled in
`mob.exs`, which is local and not in git: add `:mob_google` to
`config :mob, :plugins` and to `:acknowledge_unsafe_plugins`).

`mix mob.release` does not regenerate the Android plugin wiring; a native
debug build does. This release's wiring is already committed. After changing
plugins again:

```sh
mix mob.deploy --native --android --device not-a-real-device  # builds, installs nothing
```

Then build the sideload APK as before:

```sh
mix mob.release --android
# Mob's cached runtime ships a stale exqlite (black screen) and no inets
# (every server call fails): fix both in otp.zip.
zip -d android/app/src/release/assets/otp.zip 'lib/exqlite-0.36.0/*' 'lib/exqlite-0.36.0/' 'lib/._exqlite-0.36.0'
(cd ~/.mob/cache/otp-android-5c9c69fc && zip -qr "$OLDPWD/android/app/src/release/assets/otp.zip" lib/inets-9.7 \
  -x 'lib/inets-9.7/src/*' 'lib/inets-9.7/include/*' 'lib/inets-9.7/examples/*' '*/._*')
cd android && ./gradlew assembleRelease
# → android/app/build/outputs/apk/release/app-release.apk
```

## Checks before handing it out

- Updating from 1.1 keeps the receipts and requests, as transactions with
  their photos and attachments.
- A new number signs up with "Just me": no Approvals, no refunds.
- A business owner sees Approvals and can approve and mark paid.
- With Google configured: "Continue with Google" signs in on a real phone.
  This has been built into the app but not yet tried on a device.
